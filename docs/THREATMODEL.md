# THREATMODEL —— 抗"有狗客户脱壳再分发"的目标与当前不足

> 这份文档记录**威胁模型、目标、以及 vmp-x 当前已核实的能力与不足**。
> 所有"不足"都带 `文件:行` 依据（本轮实际读过代码），不是推测。

## 1. 威胁模型（客户给定）

- **对手**：能在目标机上**运行/调试**的人；他**持有合法的外置 HL（加密锁）**（试用或购买）。
- **攻击路径**：用合法狗跑起来 -> 取密钥 / 仿真狗 -> 产出一个**不需要狗**的版本 -> **分发**。
- **目标**：让他**拿不到可运行的等价体**（尤其是可分发的那一份）。

## 2. 诚实的结论（先说清楚天花板）

1. **"绝对拿不回可运行等价体"做不到**：任何能在他机器上运行的东西都能被 dump 与重组，
   差别只是**要花多少人月**。
2. 因此正确目标有两条、且都**可验收**：
   - **(T-a) 不可移植**：产物 + 狗搬走就不能跑（对手必须做出**通用**破解，而不是拷一份内存镜像）；
   - **(T-b) 成本高于授权价**：让"做出一份可不带狗分发的版本"的成本明显高于一份授权，
     并让**一次破解不能长期通吃**所有客户与版本。
3. **不要对外承诺**"不可脱壳/不可破解"；可承诺的是"狗绑定 + 高强度反分析 + 每客户唯一构建 + 可吊销"。

## 3. 当前**已核实**的能力（不是不足，先摆出来）

| 能力 | 依据 |
|---|---|
| 被保护函数的原生指令不在产物里（`-wipe`） | 门禁 `residue probe`（磁盘与内存都搜 native code） |
| 字节码**永不整份明文**：取指时按 64 字节块现推密钥流、逐字节 XOR | `vmb_byte`；门禁 `bytecode plaintext scan` |
| 镜像整体加密（AEAD，按节一把派生密钥，nonce 绑 rva/size/salt） | `vm_interp.c:2940-2948`；门禁 `image residue` |
| 运行期取钥接缝：**文件 -> 环境变量**，或 **严格模式只用狗**（`kind>=2`） | `vm_interp.c:1251-1262` |
| **狗取钥是真实现**（动态加载 DLL、login/read、分阶段失败码 `vm_sentinel_fail_stage`） | `vm_interp.c:1184-1224` |
| **任何解密之前**先做 KCV 自检；失败统一硬门 **`0xC0DE0007`**、无输出 | `vm_interp.c:1263-1269`、`:961` |
| 防篡改：自哈希 `vm_selfcheck`、入口补丁 MAC、KCV | `vm_interp.c` 多处 |
| 反调试 4 条路径（PEB / NtQueryInformationProcess / 调试寄存器 / 时间差），命中**静默给错结果** | `vm_antidebug` |
| 构建期可直接从狗取主密钥：`-key-in dongle:<fileID>:<offset>:<length>` | `cmd/vmpbuild/main.go:480-494` |

## 4. 当前**不足**（按对本威胁模型的影响排序，均带依据）

### G1（最大）镜像解密是"整节解密到内存"，dump 一次即得明文节
- `vm_interp.c:2940-2948`：按节 `dst = base + rva`，一次解密整节。
- 影响：持狗者跑一次、dump 内存，即得到**明文镜像**；虽然被保护函数位置是 `E9` 跳转（原文已被 wipe），
  **镜像其余部分**是明文。
- 对策：**按页惰性解密 + 用完回写**（不依赖任何新硬件，可立即开工）。

### G2 默认模式把主密钥编进 blob
- `vm_interp.c:761`："兼容模式（默认）：blob 里就带主密钥"。
- 影响：默认产物对"拿到文件的人"没有密钥门槛；有狗者更容易走到 G1。
- 注：外置模式**已存在**（`-key-external`），只是下面 G3 限制了它的适用范围。

### G3 外置密钥模式只支持 win/x64
- `cmd/vmpbuild/main.go:150`：`if *keyExternal && targetRel != "win/x64"` => 仅 win/x64。
- 影响：**i386 / Linux / arm64 没有外置密钥**，也就没有机器/狗绑定。

### G4 i386 没有镜像整体加密
- `cmd/vmpack/main.go:571-572`：`原镜像整体加密目前只支持 x86-64 / arm64（i386 先跳过这一项）`。
- 影响：32 位产物只有"VM 化 + wipe + 字节码加密"，整体保护少一层。

### G5 无吊销 / 无 features 语义
- `docs/TODO.md:474`（吊销/黑名单未做）、`:598`（`features` 语义未实现）。
- 影响：**一次破解可长期通吃**；无法按功能点或按客户收紧。

### G6 缺"狗参与密码学"的用法（只把狗当取钥/校验点）
- 已存在的 `vm_key_from_sentinel()` 是**取主密钥**；TODO `:596` 的路线 A（`hasp_login`/`hasp_get_info`/`hasp_decrypt`）尚未落地。
- 影响：对手**仿真狗**或**记录-重放**即可绕过（他本来就有狗）。
- 对策：让关键解密**必须经过狗内部非导出密钥**，并把会话/狗身份绑进密钥派生。

### G7 机器/狗绑定的其余形态未做
- `docs/TODO.md:225`（TPM/TEE/授权回调封印）、`:599`（母狗私钥保护 + `vmpbuild --key-from-dongle`）。
- 注：DPAPI **工具侧已有**（`cmd/vmpepoch/license.go:130` 给签名私钥用），但**payload 主密钥**还没有。

### G8 反调试只抬成本，不构成边界
- 4 条路径 + 静默延后；对手有调试/内核权限时只是减速带。
- 定位：成本乘数，**不能**当作"不可脱壳"的依据。

## 5. 工作项（建议顺序）

| 序 | 工作项 | 依赖 | 备注 |
|---|---|---|---|
| W1 | 镜像/字节码**按页惰性解密 + 执行后回写** | 无 | **可立即开工**，直接打掉 G1 |
| W2 | i386 补镜像整体加密 | 无 | 消掉 G4 |
| W3 | 外置密钥扩到 i386 / linux / arm64 | 无 | 消掉 G3 |
| W4 | 狗参与密码学（非导出密钥解密）+ 会话/狗绑定 | 需选定狗与 SDK | 对付 G6（有狗对手的关键） |
| W5 | `features` 语义 + 吊销/黑名单 | 与授权层同批 | 对付 G5（限制分发收益） |
| W6 | 反 dump / 反 trace 加固（检测内存被外部读取、handler 派发数据相关） | 无 | 成本乘数，配合 W1/W4 |

## 6. 可自动化验收（建议加进门禁/CI）

1. **跨机/跨狗不运行**：产物 + 密钥/狗搬到另一环境 => 必须恰好以 `0xC0DE0007` 失败；
2. **dump 不可离线运行**：运行中 dump 内存镜像后离线启动 => 必须失败（W1 的目标）；
3. **归因**：每客户构建唯一 => 从泄漏产物能反查授权编号；
4. **可吊销**：吊销后**新版本**拒绝该客户（老版本无法回收，需如实告知客户）；
5. **成本指标**：记录"重建一个 N 条 IR 的函数所需的最少 trace 覆盖"，作为持续跟踪指标。
