# vmp-x 强度自评（决定“要不要上硬件狗”的依据）

> 口径：只写**有实测证据**的能力，和**明确挡不住**的东西。目的是让产品决策有依据，
> 而不是给出一句“很安全”。所有证据都能在 `docs/STATUS.md` 对应编号里复现。

## 一、已经做到的（每条都有对应实测）

| 能力 | 证据（如何复现） |
|---|---|
| 字节码**逐条**流式解密，明文只以“寄存器里的一个字节”存在 | `tools/residue_probe.py`：内存里搜不到字节码明文；e2e 全绿 |
| 被保护函数的**原函数体**在文件与内存里都搜不到 | residue probe 的原生代码模式搜索（`--fail-on-native`） |
| 原镜像整体加密（`.text/.rdata/.data`），入口前自解密 | e2e + image residue 检查 |
| 自哈希 + 入口蹦床校验 + **入口补丁 MAC**：回填入口字节会被拒 | `tools/patch_refill.py` + e2e（实测 `0xC000001D`） |
| 反调试四路径 + 失败**静默延后**（不是崩点） | `tools/antidebug_flag_test.py` + e2e |
| 主密钥外置：产物里**搜不到**主密钥（真密钥 0 处；兼容模式对照 2 处） | e2e 的 1b 用例 + 原始字节搜索 |
| 每条目 KDF、带密钥 MAC（Poly1305）、容器字段混淆、ASLR/重定位保留 | `STATUS #383/#386/#387/#390` 各自的 KAT 与 e2e |

## 二、明确挡不住的（必须写进商务沟通口径）

1. **运行期内存抓取 / 调试**：密钥在执行期必然出现在进程里。反调试提高成本，但**不是硬件隔离** ——
   这正是“上硬件狗”要解决的问题（密钥留在狗里，进程里只有中间结果）。
2. **用户态校验可被 patch**：自哈希 + MAC + 多路径反调试把成本抬高，但**不是不可破**（专业团队能改）。
3. **VM 字节码本质是原函数的“提升”**：一旦有人 dump 出解码后的指令流，函数语义就回去了。
   这是**所有 VM 型保护的通病**（Themida/VMProtect 同样如此），不是本项目的特例。
4. **没有白盒密码学**：不防有充足时间的专业逆向 + 手工重建。

## 三、结论（对商业化意味着什么）

- 对**随手破解、静态分析、直接 dump 即用**这类攻击：vmp-x 把成本抬得很高（这是“有没有商业化价值”的分水岭）；
- 对**有充足时间、有专职逆向**的攻击：挡不住。所以商业价值不应建立在“代码不可逆”上，
  而应建立在**授权与密钥托管**上 —— 让“能不能跑”由授权层决定（Sentinel 狗 或 我们签名的授权文件），
  让“代码语义”由 vmp-x 保护。
- **两者是叠加关系，不是二选一**：
  - 已具备 Sentinel 母狗/子狗：可以让 vmp-x 的密钥/授权来自狗（密钥不出狗），破解者要同时攻破 VM 与狗；
  - 暂不上狗：用已交付的**签名授权**（Ed25519，`vmpepoch lic-*`）做“可增删、可到期、不可伪造”的授权，
    代价是授权文件可复制（无硬件绑定）、到期可被改系统时间绕过（需机器绑定/联网校时配合）。
- 一句话给销售：**“能显著抬高破解成本，并把授权做成可管理、可撤销的东西”** —— 不要承诺“不可破解”。
